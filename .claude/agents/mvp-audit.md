# MVP Audit Skill — New Level Hub

Скилл для систематической оценки реализации MVP-платформы.
Агент с доступом к кодовой базе (бэкенд + фронтенд) проходит по каждому пункту
product-скоупа и выносит вердикт: ✅ Готово / 🟡 Частично / ❌ Не сделано.

---

## Контекст задачи

Платформа состоит из 7 блоков. Фундамент частично поднят:
- Backend: Django + DRF + PostgreSQL + Docker
- Базовая авторизация (регистрация, логин, JWT, профиль)
- Кастомная модель пользователя с ролями (не доведена до конца)
- CI/CD, деплой, API-документация

Продуктовая часть (Блоки 1–7) — предмет аудита.

---

## Шаг 1 — Разведка структуры кодовой базы

Прежде чем проверять конкретные фичи, изучи структуру проекта.

### 1.1 Бэкенд
```
Просмотри корень репозитория бэкенда:
- список Django-приложений (apps/) — какие модули существуют
- models.py в каждом приложении — какие сущности описаны
- serializers.py / views.py / urls.py — какие эндпоинты реализованы
- migrations/ — что уже применено к БД
```

Составь краткую карту: `приложение → модели → эндпоинты`.

### 1.2 Фронтенд
```
Просмотри структуру фронтенда:
- pages/ или app/ (роутинг) — какие страницы существуют
- components/ — какие UI-компоненты есть
- store / context / api — какие вызовы к бэкенду реализованы
```

Составь краткую карту: `страница → компоненты → API-вызовы`.

## Шаг 2 — Чеклист по блокам MVP

Для каждого пункта ниже проверь код и выстави статус:

| Статус | Значение |
|--------|----------|
| ✅ | Реализовано полностью: модель + API + UI |
| 🟡 | Частично: например, есть модель и API, но нет UI — или наоборот |
| ❌ | Не найдено ни в бэке, ни во фронте |

При статусе 🟡 кратко опиши **что именно сделано** и **чего не хватает**.

## Правила оценки

**✅ Готово** — все три слоя присутствуют:
1. Модель/схема данных в бэкенде
2. API-эндпоинт (работающий, не заглушка)
3. UI-страница или компонент, использующий этот эндпоинт

**🟡 Частично** — хотя бы одного слоя не хватает, например:
- Модель есть, API есть, но фронтенд не реализован
- Эндпоинт существует, но не покрывает весь описанный функционал
- UI есть, но бизнес-логика не полная (например, нет валидации)

**❌ Не сделано** — ни в бэке, ни во фронте не найдено ничего, относящегося к этому пункту.

**Важно:** не додумывай и не предполагай. Если нашёл частичную реализацию — описывай конкретно. Ссылайся на файлы (`apps/bookings/models.py`, `pages/dashboard/index.tsx`), чтобы выводы можно было проверить.

## Подсказки по поиску в коде

### Бэкенд (Django)
- Роли/пользователи → `users/`, `accounts/`, `authentication/`
- Бронирование → `bookings/`, `reservations/`
- Компании → `companies/`, `tenants/`
- CRM/задачи → `crm/`, `tasks/`, `boards/`
- Уведомления → `notifications/`
- Файлы → `storage/`, `documents/`, `files/`
- Пропуска → `passes/`, `access/`, `guests/`
- Заявки → `services/`, `requests/`, `tickets/`
- Аналитика → `analytics/`, `reports/`

### Фронтенд
- Страницы → `pages/`, `app/`, `views/`
- Компоненты → `components/`
- API-вызовы → `api/`, `services/`, `hooks/`
- Маршруты → `router/`, `routes/`, `navigation/`
